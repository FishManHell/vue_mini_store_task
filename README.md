# Vue Mini Store

Full-stack take-home: a mini e-commerce SPA for digital products (e-books, software licenses, online courses, templates) with product listing, details, and a persistent shopping cart.

Vue 3 + TypeScript on the frontend, FastAPI + Redis on the backend, all orchestrated by Docker Compose. See [`TASK.md`](./TASK.md) for the original assignment.

## Stack at a glance

| Layer    | Tech                                                                            |
| -------- | ------------------------------------------------------------------------------- |
| Frontend | Vue 3 + `<script setup>`, TypeScript, Vite, Pinia, Vue Router, Tailwind, PrimeVue |
| Backend  | Python 3.12, FastAPI, Pydantic v2, redis-py (asyncio), managed by `uv`          |
| Storage  | Static JSON catalog (in-memory) + Redis (cart, keyed by client session id)      |
| Infra    | Docker Compose — redis · backend · frontend (nginx)                             |

## Quick start (one command)

```sh
docker compose up --build
```

Then open:

- **App** — <http://localhost:8080> (nginx serving the SPA, proxying `/api/*` to the backend)
- **API** — <http://localhost:8000>
- **Swagger UI** — <http://localhost:8000/docs>

Stop with `docker compose down` (add `-v` to drop the Redis volume).

## How the pieces fit

```
┌──────────┐   /api/*       ┌──────────┐                ┌────────┐
│ Browser  │ ─────────────▶ │ frontend │  ────────────▶ │ backend│
│ :8080    │ ◀───── HTML ── │  nginx   │   /  (strip)   │  :8000 │
└──────────┘                └──────────┘                └────┬───┘
                                                             │
                                                             ▼
                                                        ┌────────┐
                                                        │ redis  │
                                                        │  :6379 │
                                                        └────────┘
```

- The product catalog is a static JSON file loaded once at backend startup.
- The cart lives in Redis under `cart:{session_id}` with a sliding TTL. Identity is the `X-Session-Id` header, a UUID generated by the browser and stored in `localStorage`.
- Money is `Decimal` end-to-end, serialized as a JSON string (`"29.99"`) to avoid float drift on the client.

## Continuous integration

GitHub Actions runs on every push / PR to `main`
(see [`.github/workflows/ci.yml`](./.github/workflows/ci.yml)):

- **Frontend** — `npm ci` → lint (oxlint + eslint) → `vue-tsc` type-check →
  Vitest unit tests → production build
- **Backend** — `uv sync --frozen` → `ruff check` → `ruff format --check` →
  import smoke test → `pytest`

## Working on a single service

Each service has its own README with stack details, layout, scripts, and (for the backend) a full API reference:

- [`frontend/README.md`](./frontend/README.md) — Vite dev server, standalone Docker image, FSD layout, HTTP layer, cart store
- [`backend/README.md`](./backend/README.md) — standalone Docker image, Swagger/API checks, configuration, layered architecture

Use `docker compose up --build` when you want the full application. If you want
to verify a service independently, use the service README: the backend README
shows Redis + backend-only Docker commands, and the frontend README shows how to
start the SPA image standalone, including the `502` network-error scenario when
the backend is unavailable.
